# CLAUDE.md - Balamb Garden

Dalamud plugin for FFXIV gardening: census, timers, and one-press tend/harvest/replant chains for the household's estates. Command: `/garden`. This doc is the machine - how the code works. Product direction and design rationale live in the vault (Rebuild Spec is canonical); this file gets reviewed at every merge to main.

## Build laws (read first)

- **Always `-p:Platform=x64`.** An unflagged build produces a stale/mismatched DLL that Dalamud loads anyway. This has bitten before.
- **Agents NEVER build the plugin.** Dalamud hot-loads the output DLL - any build is a live deploy into a running game. Builds happen only on the player's explicit "go", never while they may be in-game or testing.
- **Tests are safe anytime**: `dotnet test BalambGarden.Engine.Tests/BalambGarden.Engine.Tests.csproj` - the Engine has zero game dependency.
- Feature branches only; merge to main = save point (this doc's review rides every merge - the merge gate enforces it).
- Repo is quasi-public. The maintainer persona is **Drift** (GitHub: DriftlessDigits); no real names in code, comments, commits, or docs. No AI co-authorship lines in commits. A machine-local pre-commit name guard backs this up (installed per machine from the maintainer's own tooling; untracked BY DESIGN - a tracked hook would ship the names it blocks).

## Architecture: five layers, one-way flow

Each layer knows only the layer below. **Acting IS censusing**: chains emit dialogue receipts that flow back in through the pump.

1. **Sensing** (`Engine/Sensing/` + `BalambGarden/Game/`) - stateless readers.
   - `MapSensor`: housing DataMap decode - outdoor 48-byte entries (8 beds per patch key), indoor per-pot sub-entry 0. Formats in `Engine/Sensing/MapFormat.cs` (bytes 4-5 are allocator junk - never read them). **Indoor zeroed entries are KEPT as unoccupied readings** (2026-08-28): harvest zeroes an entry in place (08-26 receipt), so a zeroed entry is the map positively saying "empty" - dropping it conflated "not settled" with "settled, all empty" and left all-empty rooms unable to prove the map answered. Consumers wanting growing pots filter on `Occupied` themselves (Water All and the replant settle poll do).
   - `ObjectSensor` / `GimmickId`: nearby bed objects - GimmickId bytes carry [bed index][patch ordinal][patch-id u16]; reach verdicts at full precision.
   - Pot identity is a **direct read** off the pot object: `HousingFurnitureIndex` + `BaseId` (= HousingFurniture sheet row). `FlowerpotSheet` derives the 3 flowerpot rows by name scan, fails loud on drift.
   - `RosterSensor` / `EstateSensor`: permission from real game data - HouseId direct equality decides "ours"; unfittable rows fail CLOSED and log raw.
   - `PotPigment`: indoor byte 2 = (pigment<<4)|stage; only receipted nibbles are interpreted, a color is never guessed.
2. **Census** (`Engine/Census/`) - the join + claim brain. `JoinShortlist` proposes patch<->key candidates from diffs; **only a receipt binds** (`JoinConfirm` - exactly one survivor or nothing). **There is no Claim() method anywhere** - claiming happens only through a completed receipted interaction (`ReceiptEvent`: Tend / Harvest / Plant / PotWater). `AccessRoster` scopes the census: not covered = not tracked.
3. **Ledger** (`Engine/Ledger/`) - `LedgerStore` persists claimed beds + bindings (file version 4 since 2026-10-15; 3 on 2026-10-14). `ClaimedBed` = **one bounded planting record per bed** (replaced the 8-observation ring, which held about one minute of per-read sightings and evicted every anchor - data inventory 2026-10-14): `Latest` (newest content read), `PlantedAt`/`PlantedBy`/`PlantedSpecies`, `StageSeen[stage] = first/last seen` (one bracket per stage, min/max fold, replay-idempotent, never evicted), `LastTended`/`LastTendedBy`/`LastTendedSpecies`, and the fence `PlantingResetAt`/`PlantingResetReason`. **THE RULE (ruled 2026-10-14)**: an older receipt never overwrites newer evidence - if it agrees with the current plant it adds its evidence (`Absorb` -> FoldedOlder), if it contradicts it goes to history only (ledger untouched, counted as replant evidence); only evidence NEWER than everything it contradicts may reset a bed. The fence only moves forward; writes at or before it are no-ops - except the player's own live acts, which are never fenced. `Rebase(reason, cut)` is the one reconcile path and is **reasoned, logged, time-aware**: every reset names a `RebaseReason` (HarvestWitnessed / ReadsEmpty / NewPlantingSighted / PotAbsent / PlantReceipt), removes only evidence at or before its cut (a sighted replant cuts at the old planting's newest content evidence; a plant receipt cuts at the sowing instant), and returns a `RebaseEvent` the plugin logs (`CensusPump.ReportRebases`: INF when anything was removed or a harvest was witnessed, DBG otherwise) and appends to the trail. **The game still wins on content mismatch**, and **a Harvest receipt rebases the record at once** (2026-08-28: the receipt is the emptying witness - the row stays, contents and clocks leave; the two-settled-reads reconcile remains for UNWITNESSED harvests only). `Hand` = own vs a wire slug - the ledger never holds a name. `DebugTrail` (trail.jsonl) is append-only evidence the engine never reads back. `GardenHistory` (`history.json`) = every Plant and Harvest from every hand, forever, with yields - the scoreboard; `HistoryQuery` is the read side (phase 2 draws the screens).
4. **Derivations** (`Engine/Derivations/`) - pure functions. Every timer is an `EtaWindow` (never a point) with `Provenance` (anchored / bracketed / estimated). `ClockWiltSource`: Watered -> Due -> Overdue -> Danger from last-tend + crop wilt hours; `DiesAt` = tend + witherHours; live stage 4 (ripe) forces NotApplicable - fully grown cannot wilt. `PotWiltRule`: a pot's map wilt byte claims water only at `wilt==1 && stage<4` (2026-08-28: ripe pots broadcast nonzero b4 while the game offers no watering verb at stage 4 - both dashboard call sites consume this one rule). `TendSweep`: whether a bed belongs in a tend SWEEP - skip only what the live map CONFIRMED ripe/empty, FAIL OPEN on map silence (the pot Water All honesty rule on beds; single-bed presses never filtered). `PipelineReader` = tips: advisory sentences over claimed plantings + CrossbreedPairs, never a planner. `PotCyclePlanner` builds full plans or refuses (never a half-plan); soil rule: exactly one soil in bags = the soil, else picker. `RunPace`: EWMA (half-old/half-new per completed unit) behind the run-log ETA - a run-lifetime average sawtoothed because chains pace the FIRST unit cheap; pace is TRACKED, never predicted (a pot sweep only learns its verb when the menu opens). Per-chain seeds match dialogue shape; `ChainBase.Eta` is thin wiring over it.
5. **Verbs & UI** (`BalambGarden/Chains/` + `Windows/`) - `ChainBase`: paced dialogue chains (human tempo + jitter, occupied-player guard, clean stop with stated reason; stops land during human-wait steps). `TendChain` (`TendOne` for deliberate single presses; `TendMany` for sweeps - the caller filters through `TendSweep` at the button, where the count is claimed, and the chain does not re-filter), `CycleChain` (harvest + replant beds), `PotChain` (pot cycle incl. full-auto plant, `WaterMany` = the pot Tend All - the button counts only occupied non-ripe pots off the live map), with `PlantFlow`/`PlantFill` doing the read-and-click (no pacing, no ledger writes). `MainWindow` = the dashboard (tab per covered estate, patch strips, exception-first water column, Watered column = `LastTended` age; its hover carries the exact local time plus the last-fed line from `ReceiptLog.LastFertilizedAt` (scanned only on the hovered row - never per row per frame); Tend All names the patches it covers AND claims only the filtered bed count, with per-patch skips in the tooltip; the amber "reads empty now - harvested?" overlay waits for `CensusPump.MapAnsweredThisVisit` - objects can settle before the DataMap on a cold zone-in, and the display believing a pre-settle empty read painted every pot amber until the retry landed). `RunLogWindow`; `ConfigWindow`.

**`EstatePort` (`Game/EstatePort.cs`) - estate teleports** (Scrooge PortOrchestrator port). THE LAW: `Fire`'s only caller is a button click - never a timer, event, or transition. Cast gate = `ActionManager.GetActionStatus` on action 5 (the game's own refusal reasons). `UpdateAetheryteList` before every read - a session that never opened the teleport window holds an empty list and `Teleport()` on it fails SILENTLY. And the call is gated on `Player.Available`: `Telepo.Instance()` SURVIVES the zone-transition player teardown, so it is not a sufficient null gate - an ungated `UpdateAetheryteList` from the draw loop mid-loading-screen crashed the client (2026-08-23). The refresh skip does not consume the throttle, so the first frame back gets a fresh list. Estate join = `TeleportInfo.HouseId` decomposed against the census `EstateKey` with EstateSensor's corroboration idiom (exact district; ward/plot off-by-one tolerance - HouseId's 0/1-based convention is unconfirmed) and the one-survivor-or-no-button rule. Room shapes match their plot: the teleport lands at the estate entrance. Button disabled while any chain runs (a teleport would strand it).

**`CensusPump` (`Game/CensusPump.cs`) is the heartbeat**: sensors read, receipts route, the ledger learns. `RefreshDisplayOnly` is the UI-read-without-recording path (post-run settle poll - do not add observations from it). Both the new-estate arrival AND the front-door inside/outside flip retry their map read until the side underfoot answers non-empty when the ledger expects content there - the DataMap populates a beat after any zone line, and a one-shot read that races it stands stale for the whole visit (2026-08-23: every FC pot record read "harvested?" against an empty flip read). `ReconcileAbsentPots`: a vanished pot entry = harvest happened unseen - but the verdict needs corroboration, because DataMap-vs-object-table settle order is unreceipted and a wrong verdict Rebase-clears real anchors: settled objects seen, map answered non-empty this visit, a prior settled read exists, and the key absent from BOTH consecutive settled reads (union spares either). Named cost: an estate harvested bare between visits keeps its amber "harvested?" rows rather than auto-clearing.

## Household sync (groundwork `sync-engine` 2026-08-23; relay LIVE + client built 2026-08-29)

**The relay serves at balamb.driftlessdigits.com** (repo DriftlessDigits/BalambRelay -> Vercel `balamb-relay` -> Neon; dumb by law - six-field envelope check only, idempotent insert per id, forward-ordered GET with opaque cursor, 21-day retention). **OPEN HOUSEHOLD (ruled 2026-08-29, supersedes the 08-28 admin split)**: the relay configures NO credential - any well-formed bearer (64 lowercase hex) IS a household, its SHA-256 namespaces the rows, two phrases = two sealed buckets, typing the phrase is the entire setup on every install. Anti-abuse = caps, not secrets: 5,000 rows/household (429, outbox holds, retention drains), 100-distinct-household fuse (paid on first write), `X-Balamb-Client` stamp as a scanner speed bump (401-uniform on stamp/auth failures). **The client is the `relay-client` arc, six pieces**:

- **HKDF contract**: `HouseholdKeys` constants are THE RELAY'S (salt `BalambGarden.HouseholdSync.v1`, info `auth-token`/`naming-key`) - realigned 2026-08-29 after shipping with an unguarded different trio; frozen vectors now pin both sides (C# test + relay's derive.test.js, same bytes forever). Phrase lives ONLY in `Configuration.SyncPassphrase` (empty = sync off, zero network surface; password field with an unmask eye). `RelayFingerprint` = SHA-256 over the bearer token string = the household's relay namespace - shown as "Household id" DEBUG-ONLY (one line, tooltip + copy; the admin/AUTH_TOKEN_HASH flow is RETIRED - open household means nothing is ever set server-side). Phrase change = NEW HOUSEHOLD: entity cache (`LedgerStore.ResetHousehold`) + parked receipts + cursor all reset (ConfigWindow).
- **HouseId banks at the ACT** (option A, ruled 08-29): the wire canonical hashes the raw 8 bytes and EstateKey is lossy, so `LoggedReceipt.HouseId` is captured at open/line time (`EstateSensor.CurrentHouseId`: indoor read inside - carries the room - general read outside - both stances field-proven 2026-08-29). 0 = honest unknown, refused at send. **First load on a v1 receipt log mints a fresh era + Version 2** - pre-houseId entries retire to history-never-cargo instead of damming the outbox.
- **Sender** (`Sync/RelaySender`): framework-tick, self-throttled (60s idle / 5m failure / 15m dam), HTTP off-thread, ack marshaled back (MarkSent + save on the framework thread only). Offline queue IS receipts.json. `WireOutbox` is the ONE place entity pseudonyms mint (pot-vs-bed dispatch lives in `EntityName.For` - byte agreement between mint sites is load-bearing); patch-id-0 / house-id-0 refusals DAM the batch at the entry (a single high-water mark cannot skip honestly); batch cap 500 = the relay's. **`Sync/RelayClient` owns the one HTTP transport** (bearer + `X-Balamb-Client` stamp on both paths); sender and poller keep only cadence + ack.
- **Poller** (`Sync/RelayPoller`): 60s at an estate / 5min idle / zone line pulls next poll to +8s. **`RelayCursor` rides ledger-v2.json** (sync ruling 9 - the cursor is a claim about what THAT FILE absorbed; piece 3 briefly put it in receipts.json, corrected same night). `RelayFeed.Parse` is all-or-nothing. Known limit: an unknown future kind word fails the parse -> backoff until upgrade.
- **Foreign replay** (`Engine/Sync/ForeignApply`, pure). **`AbsorbPage` is the whole inbox step and owns the cursor gate**: apply the page to the ledger, record its plants/harvests into the history, SAVE the history, and only on a successful save advance `RelayCursor` (a failed save holds the cursor, the page re-arrives, every apply is idempotent by id; the poller WARNs `cursor held`). Own-user skips by id; matched harvest = the emptying witness (Rebase, HarvestWitnessed); tend/potwater = `ClaimedBed.Tend` under THE RULE (an older tend naming a different known species is refused); plant = `ClaimedBed.Plant` (last edit wins - a sowing is a new planting whoever's hand; older-and-conflicting goes to history only); stage/ripe = `Absorb` (older-and-agreeing tightens the stage bracket, newer-and-contradicting resets then folds); fertilize + potwilt = honest no-ops (the game's refusal line backstops the fed race; wilt derives locally). Enums persist by NAME (`JsonStringEnumConverter`) - the hazard is renaming, not reordering. **Unmatched receipts PARK in `LedgerStore.ForeignHold`** beside the cursor (restore rewinds both together), retried on every fresh mint, pruned at 30d. Named gaps: the fed-check does not hear foreign fertilizes (foreign entries must never enter ReceiptLog or they re-ship as ours) - wants its own ruling; history from an estate this install never censused is a blind spot BY DESIGN (no access = no history, ruled 2026-10-14).
- **Entity ids mint at census time** (`CensusPump.MintWireEntities`): the HMAC inputs exist only standing at the estate. **Stance is part of the identity** - indoor HouseId carries the room, so pots mint INSIDE and beds OUTSIDE, never across the door. Cached on `ClaimedBed.WireEntity`; beds wait on gimmick scan range.
- **Observations mint on CHANGE** at the sighting seam (`SightingChange` out of OnMapSighting): stage climb -> Stage, reaching 4 -> Ripe, source `sighting`; new row / re-read / new planting emit nothing; a climb from stage-0 belief emits (more-data amendment). Honest-skip when houseId or gimmick is missing - local ring keeps it either way. PotWilt minting deliberately absent while b4's meaning stays an open watch.
- **External display** (ruling 10, amended 2026-10-14): the Watered hover says " - external" when a household hand set the clock - DERIVED from `LastTendedBy` on the record, never stored twice. Hands are opaque wire slugs everywhere (ledger, history, wire, relay, repo); the ONLY place a slug meets a label is `Configuration.HandAliases`, a local alias seat the player fills (empty = "household"). Phrase change = new household: `LedgerStore.ResetHousehold` clears every household-scoped by-field + parked receipts + cursor, and the ConfigWindow clears the alias map with it; timestamps and own receipts stay.

## Sync groundwork (built on `sync-engine`, 2026-08-23)

**The receipt lifecycle - two-phase, ratified** (vault: `Balamb Garden - Receipt Lifecycle - Design.md`, rulings 1-6). A chain's act OPENS a pending receipt; the game's own chat line CLOSES it. One receipt, two witnesses: the chain contributes armed identity, the game contributes the fact it happened.

- **Open at the ACT, never at delivery** (ruling 4). Every chain calls `CensusPump.OpenAtAct` at its commit moment - the option click, the sow Yes. Opening at delivery is the field-receipted 17:28 double-receipt bug: the line lands during the map settle, finds no pending, and the manual branch fires a second entry. The one exception is the diff-bind pot path (`_potKey` null): identity is born from the map diff AFTER the act, so it cannot open early and degrades honestly (late open, already delivered, closes chain-unconfirmed).
- **Close** = `CensusPump.TryCloseChain` on a classified line (same verb + container within `ReceiptLifecycle.CloseWindow` 6s) -> history entry, source `chain`. The desk banks a `RecentClose` memo so a delivery arriving AFTER its line already closed (`DeliveryAlreadyClosed`) does not re-open a duplicate - both race orderings field-proven 2026-08-23.
- **Timeout** (`SweepPending`): delivered but no line -> `chain-unconfirmed`, WARN, written (the count is the instrument that would earn the chat-as-primary rethink). Never delivered AND no line -> CANCEL, logged, nothing written (ruling 6: two absent witnesses = no fact).
- **Manual acts = the unclaimed close** (ruling 2): a recognised line with no pending and no chain driving becomes its own receipt via the chat-identity ladder, source `chat`. While `Plugin.AnyChainDriving`, the manual branch is CLOSED (ruling 5: one character, one pair of hands - the line is logged and dropped).

**`ChatReceipts` (`Game/ChatReceipts.cs`) - the closing half. NOT debug-gated; it ships.** Passive listener per the ObtainWatch law. Classification is a pure Engine function (`Engine/Sync/ChatLine.cs`): structure first - success = SystemMessage/57 + src=LocalPlayer, refusal = ErrorMessage/60 (never receipted) - then EXACT text match ("You spent 303 gil." rides the same structure; exact-match is load-bearing). Catalog: bed fertilize / pot fertilize / pot plant / bed tend / pot water (pot "Tend Crop" IS watering), plus **the obtain lane** (2026-08-28, from the 08-26 capture): the harvest close is `LootNotice/62 + src=LocalPlayer` with an ItemPayload - NOT 57 - and cannot exact-match (text varies by count and crop), so `ChatLine.ClassifyObtain` matches structure only and the payload's item, resolved through the species join, is the extra witness. The obtain line names no container (`ChatLine.NamesContainer`), so the pending's own container carries the close; the line's quantity is parsed and banked at close, so `harvest.yields` (reserved on the wire 08-23, shipped empty until 2026-10-14) now travels on both own harvest paths and lands in the history; a resolvable item contradicting the pending's species refuses it (times out chain-unconfirmed, honest). Manual harvests demand `HarvestCorroboration`'s MANDATORY two agreeing witnesses (item species + container's last-read species) - the obtain shape is the game's generic loot channel and a from-inventory lockbox needs no target, so absence-proceeds would mint phantom harvests. Named cost: manual FLOWER harvests never receipt (a bouquet resolves to no species); mod flower harvests close via their pending. All refusals at a garden target WARN during the shakedown (quiet the absence pair once field-proven). NOT captured yet: the bed SOW line and the hand bed-harvest path - neither has ever fired by any hand (data inventory 2026-10-14), so hand-sown beds are a named blind spot (no planted-at anchor; THE RULE keeps their waterings) until a deliberate capture session (one hand-sown bed, Watch chat on). `NoteUnmatched` (aperture 57-or-62 by the deafness lesson) logs any success-shaped unrecognised line while a pending is open as a candidate close text, but it only hears lines during a MOD chain - it is not an ambient capture. Manual identity = PREVIOUS-target at line time, defended fail-closed: kind-vs-object cross-check, plus beds-only species corroboration (`FertilizeCorroboration`, 10s window) against the crop-name inspect line (57 + src=None; FIRST LINE ONLY - the message carries a second payload behind a newline, and the whole TextValue never resolves).

**Identity: wire id = `user:era:counter`.** `user` = stable slug in Configuration (mine-vs-external forever). `era` = volatile slug in the receipt log, names one counter-life; re-minted by `EraGuard` on any of three triggers: counter rewind, fresh log, machine-fingerprint change (covers the clone/migration class a rewind check can't see). `counter` = `ReceiptLog` Seq, monotonic per era. `MachineStamp` = SHA256 of registry MachineGuid, memoized, **LOCAL ONLY - it never travels**; stored hashed in Configuration. Accepted lossy edge: full wipe = new user id, own history replays as external.

**`ReceiptLog` (`receipts.json`, via `GardenService.Receipts`)** - append-only, doubles as the sync outbox (`LastSentSeq` high-water mark; outbox scoped to the current era). Entries carry kind/source/estate/identity/data; entity pseudonyms (HouseholdKeys HMAC) mint at SEND time only - the log itself is local-plaintext. Append-only is law: a duplicate produced by a since-fixed bug stays (nothing sent), it is never edited out.

**Wire types** (`Engine/Sync/SyncReceipt.cs` + `HouseholdKeys.cs`): envelope per the ratified schema doc; enum words via `WireWordPolicy` - kebab-case default with a CLOSED pin table (`potwater`, `potwilt` stay ratified single words). `chain-unconfirmed` is a source word and must be in the relay's accepted vocabulary before the relay ships. Bed patch id (ruled 2026-08-23): the PRIMARY source is the acted object's own gimmick, threaded from the chains (`_currentBed`, banked at each gate) through `OpenAtAct`/`OnBedReceipt`; the pump cross-checks its ordinal against the menu header (`ActPatchId`) and falls back to the proximity scan only on disagreement. The send path refuses any entry still carrying patch id 0 (fail closed, one guard, no resolution machinery) - a case that should no longer arise on new receipts.

**Build stamp**: `StampBuildInfo` csproj target embeds git commit/branch/BuildTime as AssemblyMetadata (BuildTime changes every build, which defeats incremental staleness); `BuildStamp.cs` reads it; shown on the Recon tab and logged at plugin load. "Am I on the current build" is now a read, not a guess.

## Storage (plugin config directory)

- `ledger-v2.json` - the LedgerStore (filename kept; file `Version` 4 since 2026-10-15). **Fail closed**: an unreadable ledger is parked as `.unreadable-<stamp>`, never overwritten. `LedgerMigration.NormalizeEstates` runs idempotently at load (pre-08-15 files held one physical plot as two records). **Migrations run once at load, the file first copied to `ledger-v2.json.pre-v<target>.bak`** (never overwritten if present). **v2 -> v3** (`FoldLegacyRings`): each row's old ring (deserialized through `ClaimedBed.LegacyRing` - the serializer silently drops unmapped properties, so the seam has to exist) folds into stage brackets + the newest tend; only post-harvest same-species entries fold; unknown hand = null. Field-fired 2026-10-15: 60 rings folded, 70 rows, cursor and all 60 clocks preserved. **v3 -> v4** (`RenameFenceFields`): the fence fields were renamed on disk when "tenancy" became "planting" (ruled 2026-10-15; one plant's life in one bed, sow to harvest); values under the old names move onto the new ones through a read-only seam (`LegacyFenceAt`/`LegacyFenceReason`), the new name wins if both exist, the one renamed reason member maps by text.
- `history.json` - `GardenHistory`, append-only, both hands, Plant + Harvest only, dedup by wire id, born EMPTY (no back-fill from receipts.json, ruled 2026-10-14) and written on first append, not at load. Its own lifetime: a parked ledger never takes the history with it. Never the outbox.
- `trail.jsonl` - append-only receipt trail (evidence, not memory).
- `receipts.json` - the `ReceiptLog` (own history + sync outbox; see Sync groundwork). Same fail-closed park-on-unreadable rule as the ledger. **`GardenService.AppendOwn` is the ONE seam for an own receipt**: it appends to the log AND hands a plant/harvest to the history in the same call - never append to `Receipts` directly.
- The POC ledger (inside `Configuration`) is **never read** - fresh start by spec.

## Failure signatures (field-tested)

- Stale behavior after build -> the x64 flag was missing.
- `PotObject` is a record **struct** - copies mutate silently if you forget.
- UI automation: HousingGardening component nodes are Type >= 1000 (a plain node scan never sees them); buttons take `ButtonClick`, not `MouseClick`; the winning plant path is OpenForItemSlot -> context-menu Use by name -> ClickAddonButton, with settle beat + empty-slot icon baseline `0xFFFFFFFF`.
- Colored Talk names strip to base; an unresolvable Talk name lands receipts as unknown -> check `TalkAliases`.
- Outdoor wilt has **no client-side state anywhere** (DataMap + EventObject + HousingObjectManager all snapshot-diffed across a live watering: zero bytes). Prose at tend time is the only channel. Do not go hunting again without a new lead - the empty search is receipted.
- Last chain step has no successor to trigger a map re-read -> displays race; that's what the post-run settle poll (`RefreshDisplayOnly`) is for.
- Game-state singletons outlive their contents: `Telepo.Instance()` is non-null while the local player is destroyed mid-zone - gate native calls on `Player.Available`, not on the instance pointer.
- A per-read ring is not history: observing on every read saturates any bounded buffer with same-state sightings and evicts the anchors it was built to keep (2026-10-14: 446 sightings vs 29 tends, zero plant anchors survived). Keep bounded first/last brackets, not rings.
- One-shot reads of settle-async state (DataMap, object table, teleport list) are race bugs that test clean - every such read needs a retry-until-answered or corroboration pattern, and "worked in the field lap" is not evidence against a race. The DISPLAY is a consumer too (2026-08-28): the census learned to wait on 08-23 but the amber overlay kept believing pre-settle empty reads - when the recording side learns a settle lesson, ask what the rendering side reads.

## Release

The runbook is `Balamb Release` in the maintainer's private notes - run it, don't improvise. The short shape: version lives in `BalambGarden/BalambGarden.csproj` (`<Version>`), user-facing changelog in `BalambGarden/BalambGarden.json` (`Changelog`); bump both on the feature branch, merge --no-ff to main, tag `vN.N.N.N`, push tag. **The tag push triggers `.github/workflows/create_release.yml`** (thin caller into DalamudPluginRepo's reusable workflow, same as Scrooge): CI builds Release, creates the GitHub release with `latest.zip`, and pushes the version-stamped manifest to the plugin repo, whose pluginmaster regenerates itself (never hand-edit it). Requires the `PAT` secret on this repo. Dev loads read `images/icon.png` beside the DLL; `IconUrl` is fetched only for repo installs; the game caches the icon image across restarts.

## Debug-only instrumentation

`ReconProbe` (debug builds): raw hex dumped verbatim beside every decode so a decoder bug is visible, not hidden. `PlantFlow` watcher is `#if DEBUG`. `ChatRecon` (`Game/ChatRecon.cs`, whole file `#if DEBUG`): passive chat listener for manual-action capture - per line: LogKind, source/target relation kinds, sender, verbatim text, payload shape, and hard/soft/previous target decoded to bed gimmick or pot key. Manual toggle on the Recon tab ("Watch chat"); survives zone lines; never handles or suppresses a message. Key capture receipts (2026-08-23, `captures/2026-08-23-fertilize-recon.log`): manual-verb success lines are SystemMessage/57 with src=LocalPlayer, refusals are ErrorMessage/60 with src=None (wording varies, structure does not); the acted object rides PREVIOUS-target at line time (hard target is cleared by then).
